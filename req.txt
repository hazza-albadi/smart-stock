SMARTSTOCK - WHAT YOU NEED TO RUN IT ON YOUR OWN COMPUTER
===========================================================
SmartStock Live (Qeshour) runs fully on your computer: no cloud, no login, no external service, no API key.
Windows, macOS and Linux are supported. Quick start (details below):

  Windows PowerShell :  .\setup.ps1
  macOS / Linux      :  ./setup.sh
  then open          :  http://localhost:3000

Check your computer at any time with:  npm run doctor   (messages in English and Arabic)


1. SYSTEM REQUIREMENTS
----------------------
- Operating system : Windows 10/11 (x64 or ARM64), macOS 12+ (Intel or Apple Silicon), Linux (x64 or ARM64; glibc or musl/Alpine).
- Node.js          : 22 or newer.  Required by package.json "engines" ( >=22.0.0 ) because the SQLite package
                     better-sqlite3 13 needs Node >=22. Verified with Node 22 and Node 24 (see section 9). The file .nvmrc says 22.
                     Older Node (18, 20) does NOT work: install fails or the database module will not load.
- npm              : 10 or newer (npm 11 verified). It comes with Node.
- Git              : any recent version (only needed to clone the project and switch branch).
- Free disk space  : about 1.5 GB for node_modules and the Next.js cache, plus a few MB for the database. (See "measured sizes" in section 9.)
- Memory           : 2 GB free RAM is enough for the dev server.
- Browser          : any current Chrome, Edge, Firefox or Safari.
- Port             : 3000 by default (http://localhost:3000). If it is busy Next.js picks the next free one (3001 ...) and prints it.
                     Choose your own:   PowerShell:  $env:PORT=3100; npm run dev      bash:  PORT=3100 npm run dev
                     or:                npm run dev -- -p 3100
- Python           : NOT needed to run the app. Only `npm run locales` (regenerating the translation files) uses Python 3.


2. NATIVE DEPENDENCY NOTE (SQLite)
----------------------------------
The database package is better-sqlite3 (a native C++ module). Version 13 ships PREBUILT binaries inside the npm package for:
  Windows x64 / ARM64, macOS Intel / Apple Silicon, Linux x64 / ARM64 (glibc and musl).
So on a normal machine `npm ci` needs NO compiler. IMPORTANT: npm 11 would still try to compile the module with node-gyp during install
(and fail on a computer without Visual Studio / Xcode tools). The project therefore contains a .npmrc file with `ignore-scripts=true`, which makes
npm use the prebuilt binary. (Tested: without it `npm ci` fails on a clean Windows machine with "find VS ... Desktop development with C++".)
Do not delete .npmrc. Side effect: npm does not run pre/post scripts, so `npm run dev` calls the doctor itself (see section 6).
If your Node/OS combination is not covered or the binary does not load
(error mentions "better-sqlite3", "node-gyp" or "was compiled against a different Node.js version"):
  1) Check Node:           node -v            (must be 22 or newer, then open a NEW terminal)
  2) Reinstall the module:  npm ci            (or: npm rebuild better-sqlite3 --ignore-scripts=false --build-from-source  to compile it)
  3) Still failing? Install a compiler and Python 3, then run step 2 again:
     Windows : install "Visual Studio Build Tools" with the workload "Desktop development with C++"
               winget install Microsoft.VisualStudio.2022.BuildTools --override "--wait --passive --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
               winget install Python.Python.3.12
     macOS   : xcode-select --install
     Linux   : Debian/Ubuntu:  sudo apt update && sudo apt install -y build-essential python3
               Fedora:         sudo dnf groupinstall -y "Development Tools" && sudo dnf install -y python3
               Alpine:         apk add build-base python3
`npm run doctor` tests that the module really loads and tells you what to do if not.

4. REQUIRED DATA
----------------
- The folder  smartstock_data/  must be in the project root. It holds the 8 CSV files the simulation is built from
  (items, suppliers, stock_movements, current_stock, purchase_orders_open, purchasing_budget, warehouse_zones, space_requests)
  and a data dictionary. It is part of the repository.
- If it is missing: `npm run doctor` reports it, `npm run seed` stops with "ENOENT ... smartstock_data", and the page shows a
  load error. Fix:  git checkout -- smartstock_data   (or copy the folder back).
- config/defaults.json (all settings) and locales/en.json + locales/ar.json (all texts) are also required and are in the repository.


5. OPTIONAL SETTINGS (environment variables)
--------------------------------------------
None are required. Copy .env.example to .env.local (git-ignored; never commit real keys) and fill only what you need:
  ANTHROPIC_API_KEY   optional. Lets a model polish the wording of supplier messages when you press "Run analysis".
                      Numbers and decisions stay deterministic. Without it everything works with the built-in wording.
  SMARTSTOCK_MODEL    optional. Model used for that wording.
  SMARTSTOCK_DB       optional. Path of another database file (default ./smartstock.db).
  PORT                optional. Port of the dev server (default 3000).
Create the file:   PowerShell:  Copy-Item .env.example .env.local        bash:  cp .env.example .env.local
Restart `npm run dev` after changing it.


6. STEP-BY-STEP SETUP AND RUN
-----------------------------
Easiest: run the setup script (it checks Node, installs, checks the environment, seeds the database and starts the app,
and stops with a clear message if a step fails).

--- Windows PowerShell -----------------------------------------------------------------------------
  git clone https://github.com/hazza-albadi/smart-stock.git
  cd smart-stock
  git checkout feature/space-flow
  .\setup.ps1                       # if scripts are blocked:  powershell -ExecutionPolicy Bypass -File .\setup.ps1

Or by hand, one command per line (PowerShell 5.1 has no &&, so run them one after the other):
  node -v                           # must print v22 or higher
  npm ci
  npm run doctor
  npm run seed
  npm run dev
  Start-Process http://localhost:3000

--- macOS / Linux (bash or zsh) --------------------------------------------------------------------
  git clone https://github.com/hazza-albadi/smart-stock.git
  cd smart-stock
  git checkout feature/space-flow
  ./setup.sh                        # if it is not executable:  bash setup.sh

Or by hand:
  node -v && npm ci && npm run doctor && npm run seed && npm run dev
  open http://localhost:3000        # macOS      (Linux: xdg-open http://localhost:3000)

The page opens in the LIGHT theme and in Arabic (RTL). Use the language and theme buttons in the top bar; your choice is remembered in the browser.
`npm run dev` runs the doctor first (`node scripts/check-env.mjs --pre`; it only stops for problems that would break the app, such as an old Node).
Stop the app with Ctrl+C. Data is kept in smartstock.db between runs. If you skip `npm run seed`, the database is created automatically
on the first page load.


7. RESET, CHECKS AND WHAT EACH COMMAND DOES
-------------------------------------------
  npm run doctor      checks Node, npm, Git, data files, project files, the SQLite module, the port and the database; prints fixes (EN + AR).
  npm run seed        deletes and rebuilds smartstock.db from smartstock_data/*.csv + config/defaults.json = DAY 0 (Mon 5 Oct 2026, 00:00).
                      Your edited settings are reset too. Run it with the dev server stopped.
  Reset inside the app:   More menu -> "Start over" (asks for confirmation; keeps your settings).
  npm run dev         development server (hot reload).     npm run build  then  npm start   = production build on the same port.
  npm run check [h]   prints the day-0 picture (or the picture after h simulated hours) in the terminal, English. Uses its own seed of smartstock.db.
  npm test            about 70 automated tests (formulas, texts, day-0 baseline, clock, decisions, space flow). Takes 3-6 minutes.
  npm run audit 3 42  QUICK number audit: 3 simulated days, seed 42, on a throw-away database (about 1 minute). It never touches smartstock.db.
  npm run audit       FULL audit: 30 days x 3 seeds (about 15 minutes) - only before a release.
  npm run literals    scans the code for hard-coded ids, names and business numbers (must say "No hard-coded literals found").
  npx tsc --noEmit    type check.
  npm run locales     rebuilds locales/*.json from the Python wording scripts (needs Python 3; not needed to run the app).
  npm run req:update  refreshes the dependency list of this file from package.json + package-lock.json.


8. TROUBLESHOOTING
------------------
- "Port 3000 is in use" / app opens on 3001: another program (or an older dev server) uses 3000. Close it, or use another port (section 1).
  Find the process:   PowerShell: Get-NetTCPConnection -LocalPort 3000 | Select OwningProcess     bash: lsof -i :3000
- Native module / better-sqlite3 / node-gyp errors: see section 2. Most often the cause is Node older than 22. Run `node -v`, switch,
  delete node_modules and run `npm ci` again.
- "Unsupported engine" or syntax errors right after install: Node version mismatch. Use Node 22+ (nvm install 22 && nvm use 22; Windows: nvm-windows or
  winget install OpenJS.NodeJS.LTS) and open a NEW terminal.
- "database is locked" or "database disk image is malformed": stop every running copy of the app (Ctrl+C, close other terminals), then delete the
  database files and re-create them:
     PowerShell:  Remove-Item smartstock.db, smartstock.db-wal, smartstock.db-shm -ErrorAction SilentlyContinue ; npm run seed
     bash:        rm -f smartstock.db smartstock.db-wal smartstock.db-shm && npm run seed
- Windows "LF will be replaced by CRLF" warnings from Git: harmless. The repository has a .gitattributes file; to silence them run
     git config core.autocrlf true
- Blank page, old screen or odd behaviour after switching branch / updating: stop the server, delete the Next.js cache and restart:
     PowerShell:  Remove-Item -Recurse -Force .next ; npm run dev          bash:  rm -rf .next && npm run dev
  Also try a hard refresh in the browser (Ctrl+Shift+R) or a private window (the browser remembers language/theme/tour in local storage).
- The first-run tour shows again: it is remembered per browser; clear site data or use Help -> Quick tour.
- "ENOENT ... smartstock_data": see section 4.
- npm ci fails with "package-lock.json out of sync": you changed package.json; run `npm install` once, or re-checkout the lock file.
- Slow first page: the first request compiles the app (10-30 s in dev). Later pages are fast.

10. NOTES FOR THE DEMO
----------------------
- Everything runs locally and offline. The only optional network call is the ANTHROPIC_API_KEY wording polish; without a key nothing leaves your computer.
- The clock is simulated: one tick = one simulated hour, starting Monday 5 October 2026 00:00 (day 0). Press Start; "Speed" sets how many real
  seconds one simulated hour takes (default 5 s; presets from 0.5 s to 30 s; custom values allowed). The clock pauses by itself on a critical event.
- Two sections: Purchasing and Space (rental). The app opens in the LIGHT theme for every new visitor; the moon/sun button switches it.
- Help -> "2-minute demo" is the script for a presentation; Help -> Glossary explains the terms. README.md has the full explanation and docs/space-flow/ has screenshots.
- Day-0 numbers you should see: purchasing budget 18,000 OMR (3,988.500 OMR free), 7 decisions waiting in Purchasing, 2 free-space windows in Space,
  1,400 m2 physically empty (Z1 500 + Z5 900), no listings, offers or rentals.
